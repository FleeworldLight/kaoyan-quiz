## 二、来源勘察：逐个来源的可用性结论

### 1. 本地 PDF 实测（关键突破点）

本地 `cs-408-main/cs-408-main/408真题/` 下其实有**三套**不同来源的 PDF，可读性完全不同。任务简报里说的
「真题 PDF 中文乱码」只对其中一套成立。

|---|---|---|
| A「真题」套 | `2009-2023真题/*.pdf` | **大部分乱码**。2009/2010/2011/2013/2016/2018/2020 中文全部丢失（PDF 缺 ToUnicode CMap）；2012/2014/2015/2017/2019/2021/2022/2023 可读 |

| C 完美打印版 | `2009-2013年计算机408真题完美打印版.pdf` | 可读（2009–2013，仅题干无答案） |

## 四、答案可信度验证

答案（`answer` 字段）**全部来自 PDF 文本层，没有任何模型推断**。为了确认没有解析错位，做了三重交叉验证：

### 1. 同一文件内多策略互证（构建时自动执行）

对每个年份从答案 PDF 中并行跑 6 种互相独立的抽取策略（`【参考答案】X` / `X。【解析】` / `X解析：` /
答案区首字母 / 逐题定位 / 答案清单递增链），然后比对。`_manifest.json` 的 `diagnostics` 里记录了
每年各策略的覆盖数与冲突项。

**结果**：15 年中有 12 年出现至少两条独立策略都能完整覆盖 1–40，且**答案完全一致**。
唯一出现的分歧是「逐题定位」策略在第 40 题上与其它策略冲突（如 2016 q40：清单法=C、逐题法=D），
经人工回查原文 `40.【参考答案】C【解析】…`，**清单法正确，逐题法因第 40 题段落延伸到文末而误取**。

### 2. 两个独立本地文件互证

`2009-2016真题&答案/*.pdf` 与 `2009-2023答案/*.pdf` 是两套不同来源的答案 PDF。用独立的简化抽取器
对同一年份分别抽取并比较（脚本 `tools/xcheck.mjs`）：

| 年份 | qa-<年>.txt | ans-<年>.txt | 结论 |
|---|---|---|---|
| 2009 | 40/40 **一致** | 40/40 **一致** | 双源确认 |
| 2010 | 40/40 **一致** | 40/40 **一致** | 双源确认 |
| 2012 | 40/40 **一致** | 40/40 **一致** | 双源确认 |
| 2014 | 40/40 **一致** | 40/40 **一致** | 双源确认 |
| 2015 | 40/40 **一致** | 40/40 **一致** | 双源确认 |
| 2011 | 该文件正文无答案清单 | 40/40（`解答：X。` 格式，正文可见） | 单源，格式明确 |
| 2013 | 40/40（`N. X解析：`） | 该文件中文丢失 | 单源，格式明确 |
| 2016 | 扫描件 | 40/40 | 单源 |
| 2017–2020, 2022, 2023 | — | 40/40 | 单源 |

2011 年答案串 `ABBCCDACBABDABDACDCCDCBADBDDABBCABBDDCCB` 直接来自答案 PDF 中
`1．…解答：A。 2．…解答：B。 …` 的逐题标记，人工核对一致。

### 3. 2021 / 2022 的特殊情况

- 2021：本地 `2021答案.pdf` 是扫描图。改用 JDC2001/408 的 `2021答案.pdf`（文本层中文 6771 字）。
  其中 q7 的解析标记在 OCR 中写成了 `【解析）`（右括号错成）），已做兼容处理。
- 2022：本地答案 PDF 的 q38 答案字母是小写 `38. c.`，已做大小写兼容。

### 4. 2024 / 2025 采用完全不同的验证方式

这两年**没有可读的答案 PDF 文本层**，改成「两个独立文本来源 + 官方扫描件 OCR 仲裁」的三源互证，
详见 **第八节**。核心结论：三方在可读范围内 0 冲突，答案 100% 有来源、无任何模型推断。

## 六、已知缺陷（按年份）

### 6.1 卷级共性缺陷（全部 17 年）

1. ~~**完全没有采集图片**~~ → **2026-10 已补齐配图**：从 rebuild PDF 抽出 121 张内嵌图，
   挂到 110 道题、141 处引用，见**第十节**。源 PDF 里还有 12 道题的插图本身没有内嵌图（强引用），
   这些题仍会走前端 `figureMissing()` 的「对照原卷」提示；`_manifest.json.knownLimitations` 已同步更新。
2. **公式上下标丢失**：题干/选项来自 PDF 文本层，上下标会退化成普通字符，例如
   `O(log2n)`、`O(n2)`、`232`、`2n`（原文是 O(log₂n)、O(n²)、2³²、2ⁿ）。未做 LaTeX 重写（避免臆造）。
3. **选项中的公式排版串行**：如 `B. 0.97×109 条指令/秒`（原文 0.97×10⁹）。
4. **表格类题目**：题干中的表格被抽成连续文本（如 2016 q1 的内存状态表），可读性较差但信息完整。

### 8.2 答案：为什么不能用官方答案 PDF

`answers/2024-answer.pdf`（6 页）与 `answers/2025-answer.pdf`（5 页）**都没有文本层**：

```
rebuild-ans/2024.pdf -> ans-2425-2024.txt: pages=6 chars=60 cjk=0
rebuild-ans/2025.pdf -> ans-2425-2025.txt: pages=5 chars=50 cjk=0
```

但这两份 PDF 内部是 **DCTDecode(JPEG) 扫描图**，于是把它们逐张抽出来
（`tools/extract-ans-images.mjs` → `tools/cache/alt/scan/*.jpg`），
再用 **Windows 自带 OCR（`Windows.Media.Ocr`，zh-Hans-CN）** 识别
（`tools/ocr-scans.ps1`；识别前用 Pillow 放大 3× + 自动对比度 + 锐化，见 `tools/cache/alt/scan-big/`）。

OCR 能稳定读出的选择题答案：**2024 年 26/40、2025 年 30/40**（答案速查表的密集排版会漏字，
因此只作为**仲裁证据**，不作为主来源）。

|---|---|---|---|
| **csgraduates.com 408 真题精讲**（仓库 `dyuebug/csgraduates`，`study_methods/408quiz/<year>/content.md`） | 主来源：单选答案＋解析、41–47 参考解答 | 单选 40/40、综合 7/7 | 单选 40/40、综合 7/7 |
| **408os.cn 题库**（仓库 `kaichan-kc/408-questions`，`408_questions_by_year/<year>.json`） | 第二来源：单选答案＋解析 | 单选 40/40 | 单选 40/40 |

## 十、配图采集（2026-10 增量，本次新增）

> 脚本：`tools/attach-cs408-images.mjs`（已并入 `npm run data:cs408`，排在 `build-cs408.mjs` 之后）
> 明细报告：`tools/cache/img/attach-cs408-report.txt`；逐题对照表：`tools/cache/img/attach-cs408-map.md`
> 图片目录：`public/data/cs408/images/`（121 个 PNG，即 `cs408-<year>-p<page>-<序号>.png`）

### 10.1 做法

- **抽图**：对 `tools/cache/rebuild/<year>.pdf` 逐页 `getOperatorList()`，遇到 `paintImageXObject` 就取图。
  用算子流里的 CTM（含 `save/restore`、`transform`、`paintFormXObjectBegin` 的 form matrix）算出图在页面坐标系里的矩形，
  重叠上 form 的裁剪框得到实际可见区域。121 个图算子全部取到像素，**没有掩膜图、没有内联图**。
- **编码**：`page.objs.get(name, cb)` 拿到 `{width,height,data,kind}`（RGB/RGBA/灰度），
  用自写的 PNG 编码器（`zlib.deflateSync` + 手写 IHDR/IDAT/IEND/CRC32）落盘，**没有引入任何新依赖**。
- **定位**：同一页用 `getTextContent()` 找题号（★ 顶格行、形如 `1.`~`47.`，47 个题号在 17 年里全部定位成功、零缺失），
  再按下面的优先级把图分配给题目：
  1. **图注**：图的上/下 45pt 内最近一行若是「题 N 图」→ 归第 N 题；若是「题 N～M 图」→ 归 N..M 整段
     （2016 的「题 33～41 图」因此同时挂给 33–41 共 9 道题）。
  2. **右侧图**：某题号的行落在图的纵向区间内、且该行文字整行都在图的左边（水平不重叠）→ 归该题
     （命中 2009 q3、2010 q4/q34、2012 q7、2017 q5、2020 q5/q7、2022 q45/q46、2023 q5 等「图在右、与题干同行」的排版）。
  3. **默认**：图的顶边 y 落在「本题题号 y」与「下一题题号 y」之间 → 归本题；
     若本题题干不含图字样、而图的下方那道题题干含图字样且图被排在了它上方 → 归下面那道题（2022 q7 的 AOE 图就是这样找回来的）。
  4. **交叉引用**：题干里写「题 K 图」而图挂在第 K 题时，把同一批文件也挂到本题（2014 q43 ← 题 42 图；2018 q45 ← 题 44 图）。
- **过滤规则**：占页面积 ≥55% 视为整页背景、像素 <12×12 视为装饰小图、非白像素 <0.2% 视为空白图，一律丢弃。
  **本次 121 张全部通过，一张都没丢**。另外会清理上一轮遗留、这轮不再引用的 PNG。

### 10.5 复现（重要）

```powershell
$node = "node"
cd <项目根目录>

& $node tools\build-cs408.mjs          # 1) 重新生成 17 份卷子（此时 images 全为空）
& $node tools\attach-cs408-images.mjs   # 2) 从 rebuild PDF 抽图 + 挂图（≈1 分钟）
& python tools\optimize-images.py       # 3) 把 PNG 压回去（见下，必须手动跑）
& $node tools\validate-all.mjs          # 4) 校验（含「images 引用的文件必须存在」）
```

- `package.json` 的 `data:cs408` 现在是 `node tools/build-cs408.mjs && node tools/attach-cs408-images.mjs`，
  两步都会在 `data:build` 里跑到；**`attach-cs408-images.mjs` 可反复重跑**：重跑后 17 份 JSON 与上一次逐字节一致（已实测）。
- ⚠️ **重跑抽图会重新生成未压缩的 PNG（当前约 29.4 MB）。图片压缩不在 npm 流水线里**
  （Node 侧没有纯 JS 的 PNG 量化实现），所以**抽图之后必须手动跑一次 `python tools/optimize-images.py`**
  把图压回去（自适应调色板，30.8 MB → 14.9 MB，PSNR 48–99 dB）。忘了跑不会报错，只会让仓库体积变大。
- `attach-cs408-images.mjs` 还会顺手把 `_manifest.json` 里那条过时的「所有题目均未采集图片」
  换成实际配图情况，并写入 `manifest.images` 概要（文件数/字节数/带图题数/复现命令）。
  注意：`manifest.images.bytes` 记的是**压缩前**的体积，跑完 `optimize-images.py` 后这个数字会偏大。
- 校验脚本 `tools/validate-all.mjs` 新增：每道题 `images` 里引用的文件必须在
  `public/data/<subject>/images/` 下真实存在且非空（当前 170 处引用 / 150 个文件，0 ERROR）。
